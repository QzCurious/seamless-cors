# Dynamic System PAC lifecycle

Status: accepted

This decision supersedes the PAC integration and Stop-cleanup portions of ADR-0001, ADR-0002, ADR-0006, ADR-0009, and ADR-0011. The previous activation-scoped Control and fixed service set made lifecycle and reporting more complex without protecting additional user state, so they are replaced by one deep System PAC module exposing three synchronous operations: deliver to a required PAC Endpoint, inspect current settings, and clean up owned PAC state. System PAC owns publication generation, current Network Service discovery, PAC ownership classification, safe mutation, serialization, and verification; the separate Network Service module continues to hide platform mechanics.

Manageability is derived from each observation: empty and marker-owned settings are manageable whether enabled or disabled, while foreign settings and failed reads are not. Ownership remains a separate marker predicate for cleanup; an empty setting is manageable but not owned. Reports expose manageability, observed URL and enabled state, and read errors, with ownership retained as a concrete fact for cleanup classification rather than a multi-state enum.

Every System PAC Delivery allocates a new publication generation, freshly observes every currently visible Network Service, changes only empty or marker-owned settings, and freshly verifies the resulting state. Foreign and unobservable settings are preserved, successful services are not rolled back, and failed or partially successful attempts consume their generation. Initial start, every effective Traffic Projection change, and repeated start each request their own serialized delivery through ordinary backpressure; requests are neither conflated nor retried by background polling. Delivery failure, including having no safely mutable service, does not prevent Gateway Runtime from starting or continuing.

Delivery and cleanup are commands returning only concrete errors; inspection alone returns an Observation with available facts and read errors. The former shared State mixed publication intent with observed settings, so publication generation stays private and is no longer returned or surfaced separately. Delivery succeeds only when at least one service was eligible, all eligible services are verified enabled with the exact intended publication URL, and no discovery, read, write, or verification error occurred; no eligible services and an observed publication mismatch are distinct concrete errors. Gateway explicitly inspects after delivery or cleanup when constructing their surface-neutral System PAC Reports, combines command errors with that inspection, retains exactly one latest delivery report as historical diagnostics, and asks System PAC for fresh observation when producing current status. Command verification stays internal; a subsequent inspection is a separate read and does not retroactively change command success. Observation always reports every visible Network Service and exposes a Routes Current Endpoint predicate for a supplied endpoint; foreign PAC is ordinary excluded state rather than drift or failure.

Every `stop` attempts System PAC Cleanup and Gateway State Cache cleanup whether it finds a start-hosted owner, a router-only `serve` owner, or no owner. With a live runtime, delivery triggers are cancelled and System PAC Cleanup runs while traffic endpoints still serve, after which runtime and owner shutdown continues. Cleanup disables and verifies active marker-owned settings while preserving foreign, disabled, and unobservable settings. Discovery, observation, mutation, or verification uncertainty makes the cleanup sub-operation unfulfilled and is prominently reported, but Stop itself remains fulfilled and exits successfully after its best-effort attempts. There is no separate cleanup command or previous-PAC restoration.

The clean break removes the old Control model, terminal PAC-specific Start outcomes, generic runtime-status notifications, and the conflating stream helper; UserCA assessment and System PAC delivery use separate ordinary channels.
